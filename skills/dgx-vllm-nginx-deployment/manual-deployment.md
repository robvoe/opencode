# Manual deployment runbook

This runbook is loaded and used by `SKILL.md` for manual mode and as the
canonical command sequence for automatic mode. Replace every `<placeholder>`
with values collected during grilling. Do not edit this file during a run.

## 1. Preconditions

Run from the local machine with an active `dgx` SSH alias or another approved
DGX transport. All remote commands below run from the head node unless noted.

```bash
ssh -o ClearAllForwardings=yes dgx 'hostname'
ssh -o ClearAllForwardings=yes dgx 'module load slurm; command -v srun squeue scontrol'
```

Discover the worker and GPUs. Do not assume node 2:

```bash
ssh -o ClearAllForwardings=yes dgx \
  'module load slurm; scontrol show node <worker>; squeue -w <worker>'
```

Fetch the current Confluence User Port mappings before selecting model ports.
Reserve one consecutive port per confirmed GPU and one separate LB port.

## 2. Deployment variables

Set these only after user confirmation:

```text
DEPLOYMENT_ID=<unique label>
USER=<authenticated DGX username>
WORKER=<confirmed Slurm worker>
GPU_COUNT=<explicitly confirmed count; recommend 4, never assume>
MODEL_IMAGE=<explicit versioned pyxis image>
MODEL_PATH=<validated model name or worker-local cache path>
MODEL_PORTS=<one user-range port per GPU>
LB_IMAGE=external.cr.mam.dev#/library/nginx:1.31.4
LB_PORT=<confirmed public/LB port>
CERT_SOURCE=<user-supplied certificate path on worker>
KEY_SOURCE=<user-supplied key path on worker>
TMUX_SESSION=<discovered attached/default session>
```

Use these staging directories only for runtime artifacts:

```text
HEAD_STAGE=/tmp/<user>/<skill-name>-<deployment-id>/head
WORKER_STAGE=/tmp/<user>/<skill-name>-<deployment-id>/worker
```

If any destination exists, copy it to a timestamped backup before writing.
Render and validate new files separately; never edit the skill folder.

## 3. Replica launcher

Copy the companion scripts to `HEAD_STAGE`, render a per-deployment serving
script, and copy it to the worker stage. The launcher must request one GPU per
replica and use a distinct port:

```bash
PORT=<model-port> \
MODEL_IMAGE=<model-image> \
WORKER=<worker> \
DEPLOYMENT_ID=<deployment-id> \
<skilldir>/run-vllm-replica.sh
```

The launcher must use:

```text
srun --pty --interactive
--container-image=<MODEL_IMAGE>
--nodelist=<WORKER>
--gres=gpu:1
--container-mount-home
--container-mounts=/export:/export,/scratch:/scratch
--container-writable
--no-container-entrypoint
```

Each replica runs in its own window named with the deployment label and port,
for example `<skill-name>-<deployment-id>-50064`. Create windows in the
discovered default session using a session-qualified target, not `-t 0`.

## 4. First replica gate

Start only the first replica. Verify:

```bash
curl -sS -m 15 http://<worker>:<first-model-port>/v1/models
```

Run one non-streaming chat request and one streaming request. If vision is
supported, send `<skilldir>/assets/vision-fixture.jpg` as a base64 data URI:

```python
import base64, json
image = base64.b64encode(open("<skilldir>/assets/vision-fixture.jpg", "rb").read()).decode()
content = [
    {"type": "text", "text": "Describe the image briefly."},
    {"type": "image_url", "image_url": {"url": "data:image/jpeg;base64," + image}},
]
```

Only after the first replica is healthy may the remaining replica windows be
started. If any replica fails, preserve logs and ask whether to retry, reduce
the count, or abort.

## 5. nginx configuration

Render `<skilldir>/nginx.conf.tmpl` with the confirmed LB port, certificate/key
paths, and exactly one upstream per healthy model port. The template must use a
shared upstream zone:

```nginx
upstream vllm {
    zone vllm 64k;
    least_conn;
    server <worker-ip>:<model-port> max_fails=3 fail_timeout=30s;
}
```

Validate inside the selected nginx image with the actual read-only mounts:

```bash
/usr/sbin/nginx -t -c /config/nginx.conf
```

Ask for confirmation before installing the validated config or restarting an
existing LB. Start nginx in a visible window in the same default tmux session:

```bash
<skilldir>/run-nginx-lb.sh
```

nginx mounts the user-supplied certificate/key read-only. It listens with TLS
on `<LB_PORT>` and proxies plain HTTP to the model ports.

## 6. Verification

Run `<skilldir>/verify-deployment.sh` or equivalent checks for:

1. Every requested model port.
2. nginx `/v1/models`.
3. Non-streaming chat through nginx.
4. Streaming SSE through nginx.
5. Vision through nginx using the local data URI.
6. The exact user-provided Kong URL, for example
   `/dgx/llm-large-2/v1/models`.
7. One direct model port only if the user opened its SSH forward.

Do not claim success from stale tmux scrollback. Use fresh requests and report
each endpoint independently.

## 7. Benchmark

```bash
<skilldir>/benchmark-vllm.sh <direct-url> 48
<skilldir>/benchmark-vllm.sh <lb-url> 48
```

The direct baseline is optional only when its forward is unavailable. Keep the
workload and concurrency identical. Report success rate, requests/s,
completion tokens/s, total tokens/s, and latency min/p50/p95/max.

## 8. Cleanup

Cleanup is never automatic. List current-session resources first. Ask
separately before stopping Slurm jobs, closing tmux windows, and removing the
volatile stage. Never infer ownership from a port alone.
